# Video-to-Note

把视频中的实际内容整理为可追溯的笔记。用户要求工作流时，补充可执行步骤和提示词，并标明哪些是作者做法、哪些是你的补充。先报告获取结果和材料范围，再报告内容结论。不要凭标题、简介、评论或抽样片段代替视频总结。

## 环境与任务目录

环境配置和命令见 [references/local-environment.md](references/local-environment.md)，执行前只检查本次要用的工具。下载或转录准备时间不计为已处理视频时长。

- 每次创建当前工作区 `work/video_tmp/<随机任务ID>/`，记录绝对路径。原始下载、标准音频、转录检查点和临时截图放在这个目录。
- 同一目录只允许一个写入进程。重试使用原目录；改变来源、模型或语言时创建新目录。
- 用户提供的原文件只读，不能复制进临时目录后把复制路径误当成原始来源。
- 先确定选中的单个视频/分P；合集范围不明确且影响任务时再询问，不默认批量处理。

## 1. 先字幕，再音轨

先取得标题、视频标识、选中分P、时长和可用字幕，清除链接中误夹的文字及跟踪参数。保留原始来源链接和规范链接。

| 材料 | 路线 |
|---|---|
| B站 | 先用公开接口或已经连接且获授权的字幕工具；没有可信字幕时用 `bili audio --no-split -o <task_dir>` 取音轨。使用已配置的 bili-cli；失败后根据报错与可用平台工具切换，Agent Reach 已安装时可查其 B站说明 |
| YouTube | yt-dlp 先取所需字幕；没有可信字幕时取音轨。只在需要画面时下载视频流 |
| 其他网站 | 先尝试现有平台工具或 yt-dlp；失败后按具体报错处理，不以“支持该平台”保证成功 |
| 本地音视频 | 优先读取已有字幕；否则对原文件运行本技能的转录脚本 |

确认字幕的视频/分P标识、语言、是否为空、起止时间和是否存在大段遗漏。时间覆盖不能证明内容准确，也不能把字幕末尾未到视频终点的正常片尾静音误判为缺失。需要结合画面或音轨判断。

先尝试公开材料，不默认提取浏览器 Cookie、登录或安装额外渠道。确需用户登录态时采用已授权的平台流程，不把凭据写入笔记或日志。

同一失败最多做两次有明确变化的尝试，例如更换官方备用媒体地址。不要循环重试相同请求、自动修改代理或把连接失败当作视频不存在。失败后保留已取得材料，说明具体缺口。

## 2. 音轨先试转录，再完整处理

没有可信字幕时，以音轨为主材料。使用 [scripts/transcribe.py](scripts/transcribe.py)：

1. 先运行 `--pilot` 处理第一分钟，检查能否加载模型、识别内容、语言和速度。试转录状态始终不是完成状态。
2. 试读可用后，运行相同命令但去掉 `--pilot`，自动从已完成的一分钟检查点继续。
3. 读取生成的 `transcript.json` 的全部内容；长文本分段读取再整合。

脚本将媒体转换为 16 kHz、单声道 PCM16，再以 NumPy 数组传给 faster-whisper，避开 PyAV `metadata_errors` 兼容问题。按一分钟处理并原子保存检查点；中断最多需要重新处理当前未完成的一分钟。原文件不会改写。

优先使用已有缓存模型；无缓存时根据语言和准确度需求选择，CPU 先考虑 `small`，专业术语多或试读不够准确再选择较大模型。脚本要求明确指定模型，默认禁止下载；确需新模型才加 `--download-model`。不要为了模块导入而下载模型，也不要静默换小模型。

脚本的 `completed: true` 只表示完整消费了音轨处理范围，不代表每句话正确。检查 `needs_review`、空语音块、异常重复、关键术语、数字和听起来不通顺的段落；有疑点时回听对应位置。没有完整转录时不能声称已听完音轨。

一分钟分块可能截断跨边界的词句；重要结论或逐字引用落在分块边界附近时，回听跨边界的短音轨核对。

只运行一条完整的主识别路线；先验证小段材料，再决定是否切换，不默认同时跑全片 ASR 和全片 OCR。可以并行做确实独立的下载或画面提取。后台任务每次等待不超过60秒，按有意义的进展更新用户。

## 3. 必要画面与 OCR

先读取 [references/frame-selection.md](references/frame-selection.md)，按章节、正文变化和讲解时间点选取关键画面，并保存截图清单。

代码、公式、操作流程、表格、图像及工具名称等语音不能充分表达的内容，要提取相关时间点的画面核对。先查看少量缩略图定位章节，再按疑点取清晰截图，不默认每秒提取全片截图。

OCR 用于图中文字核对或无可用音轨/字幕时的备用路线。先试识别几个代表性画面，确定字幕区域和对比度处理，再扩大范围；用相邻帧合并重复字幕，避免把幻灯片正文、页脚和水印混成口述内容。

低质量 OCR、大段缺失、无法辨识的公式或关键名称必须复核原图或回听；未解决时列出具体时间范围，并保留材料。全片采样、OCR 行数和最后时间点均不是“全片内容核验通过”的证据。

无音轨的视觉视频可以采用完整视觉阅读路线，但必须说明范围，记录章节与关键画面证据，不能生成虚假的语音转录。

## 4. 笔记与持久证据

按用户需要的篇幅生成笔记，默认包含标题、来源、时长、材料类型、一句话摘要、主题要点和关键时间点；不附完整逐字稿。工作流仅在用户要求或视频本身适合操作复用时加入，包含输入、动作、产出和必要的完成条件。

- 区分原视频事实、作者观点/案例和补充建议；作者展示的速度、数量和主观推荐不写成普遍保证。
- 笔记明确写出已处理的范围、所用材料与影响理解的缺口。不要把“字幕覆盖全片”写成“逐句核验全片音轨”。
- 首选用户指定位置；未指定时使用现有 Obsidian `视频笔记`，如果不存在或不可写，保存到当前工作区 `outputs/` 并报告。已有同名文件使用唯一后缀，不覆盖。
- 必要截图放进持久附件目录，使用 Markdown 图片链接，笔记和附件不得依赖临时目录。
- 同时保存与笔记同名的 `.evidence.json`，只保留关键证据片段和核对记录；不默认保留整段音轨逐字稿。格式见 [references/evidence.md](references/evidence.md)。

## 5. 内容检查和清理

先由你阅读并核对材料，确认每个章节的主要概念、方法、例子、结论已进入笔记，检查重要名称、数字、引用、公式和操作步骤；将具体证据写入记录。允许章节长度不同，不能按固定段数判断完成。

证据记录包含各章节的时间范围和核对位置、关键细节、主要材料是否完整，以及未解决的缺口。静音或重复片段可以记为没有实质内容，不能虚构摘要填满时间轴。

然后运行 [scripts/finalize.py](scripts/finalize.py) 验证：来源、章节范围、完成状态、持久笔记与附件、未解决的缺口。脚本只验证记录和文件，不能替你完成语义核对；不能为了让脚本通过而填写虚假的 `reviewed` 或 `passed`。

所有选中材料已处理，内容核对通过，笔记、证据与附件回读成功后，再加 `--clean`。删除仅限当前工作区 `work/video_tmp` 的一个直接子目录，并检查目录及子项无符号链接/junction/重解析点。用户原文件、模型缓存、笔记、证据与持久附件不删。失败或缺口未补全时，保留媒体和检查点，不进入清理。

收尾报告：标题与时长、总结内容、实际使用的材料、笔记位置、清理结果和仍有的限制。静态校验、导入成功和短片试转录只按实际范围报告，不能当成全片处理验收。
